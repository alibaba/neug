# 分块 COW、并发 Insert 与局部 Checkpoint 优化

## 1. 目标与确定边界

将复制、整理和持久化缩小到 chunk 粒度，保留现有事务语义和并发 Insert 快路径：

```text
COW 更新目标块 / MVCC 并发追加
    → checkpoint 按需局部 compact
    → 写入变化块与目录
    → 原子发布 checkpoint
```

- 覆盖定长属性、变长属性、时间戳、主键映射和 CSR。
- **保留 bundled 与 unbundled 两种边布局；bundled 不增加全量 EID 定位表。**
- checkpoint 保留现有写入互斥边界，不增加后台并发 checkpoint。
- 新版本直接读取旧 checkpoint，首次成功 checkpoint 转换格式；此前保持旧布局和旧 WAL 的兼容模式，此后才启用分块布局及带 EID 的新 WAL。
- 用户侧 Cypher、Python 和事务 API 保持不变。
- 第三方索引通过能力接口接入增量持久化；未支持的索引保留整模块处理，单独统计成本。

## 2. 数据布局、边身份与持久化目录

### 逻辑范围与物理生命周期

参考 zvec 的 writing Block 固化后在同一 Segment 中继续创建新 Block 的做法，将三层边界独立管理：

| 层次 | 职责 | 边界 |
|---|---|---|
| 逻辑 chunk | VID/EID 定位、版本和修改范围 | 固定 ID 范围，不随封存、删除或文件搬迁改变 |
| 物理块或数据段 | 承载数据、追加和封存 | 按容量或维护边界，可作为逻辑 chunk 的前缀、后缀或子页 |
| 对象文件 | 打包写盘及文件回收 | 包含多个块或数据段，目标 64 MiB |

物理追加块依次经历可写、停止预留并排空在途写入、封存、持久化；事务可见性仍由原有提交机制决定，封存不等于事务提交或 checkpoint 发布。checkpoint 封存未满物理块后，后续 Insert 在原逻辑范围内追加独立后缀，不修改 `rows_per_chunk`，也不复制旧前缀。物理引用记录其覆盖的逻辑槽位范围，避免按存活行数重新编号。

### 属性分块

每列持久化固定的 `rows_per_chunk`，按 **256 KiB** 目标载荷和单行宽度选择二次幂行数：

```text
chunk_id   = row_id / rows_per_chunk
local_slot = row_id % rows_per_chunk
```

顶点属性使用 VID，unbundled 边属性使用稳定 EID。不同列允许不同块行数，扫描按列块边界切分批次；增长只增加新块，不重新划分已有范围。

- 定长属性、时间戳和删除状态分别分块。
- VARCHAR/LIST 使用固定大小的行描述符块，以及独立数据段；数据段须支持 WAL 前预留/新分配（见本节末「变长与 bulk COPY 结论」），以修复 §5.4 的零冗余限制。
- 描述符保存数据段身份、偏移和长度；NULL 与空值独立表达。
- 普通数据段目标 256 KiB，归属于一个描述符 chunk，不跨描述符 chunk 混用。
- 超大字符串使用独立大段；LIST 使用类型化元素段，嵌套类型递归组织。
- 整值更新追加新内容并替换描述符，不复制整个旧数据段。
- 数据段生命周期 `appendable`（可写，含预留 tail）→ `sealed`（封存，不可变）：追加写进当前 appendable 段的预留 tail，tail 满则封存当前段并分配新段。
- 读者稳定性是 §5.4 根本解关键：sealed 段对读者不可变、读者 pin 段版本，封存/新段分配不触碰旧读者在用的段——由此解耦「容量增长」与「读者稳定性」，并发 insert apply 不再需要 resize 变长缓冲。
- 内建主键映射采用键列分块、哈希桶分页及局部分裂。

变长与 bulk COPY 结论（#6 分析）：

- **§5.4 必须修，且是预占协议的前置依赖**：当前 `ListPropertyColumn`/`VecColumn` 从 checkpoint 加载后变长缓冲零冗余（`elements_tail_ == elements_->size()`），插入路径 `insert_safe=false`（`graph_view.cc` 断言）在长度变化时必抛 `StorageException`。这与 §3 预占协议“WAL 前预留变长空间、WAL 后不再扩容”直接冲突。分块的“独立数据段”必须在 WAL 前按事务变长载荷预留空间或新分配段，使 WAL 后 apply 只写入预留区、不 resize、不抛——否则步骤 5 的不可失败 apply 无法兑现，触发 fail-stop。
- **§5.4 根本解 = append-oriented 稳定段，明确拒绝止血带**：根因是并发 insert 多事务并发 apply，变长 resize 重分配 buffer 会使并发读者失效，故被迫 `insert_safe=false`。当前连续 mmap 列架构下任何有限冗余（如 StringColumn 式 ~25% spare）都只是**有界缓解、非根本解**，且分块落地后为 throwaway——明确拒绝。根本解靠上述 appendable/sealed 段生命周期解耦「增长」与「读者稳定性」 + WAL 前精确预留，使任意变长载荷 apply 不可失败；此路径 gated on §5 step1 块目录/对象切片/GC 地基。
- **bulk COPY 须映射为只写脏 chunk**：当前 `DumpDirtyAndReopen` 对脏表整表 `DisassembleTo`（`property_graph.cc` 已 WARNING “repeated bulk writes...full-table rewrite”），同表 K 次 COPY 写放大为 B×K(K+1)/2（二次方）。分块局部 compact 须把 COPY 改为只持久化新增/脏 chunk → 线性 B×K。例：K=100 次同表 COPY，整表重写 5050×B vs 分块 100×B（省 50×）。文档需显式把分块模型映射到 `BulkCowGraphStorage`→checkpoint 路径。

### Bundled 与 unbundled

两种布局共用边表内稳定 EID。EID 在边表层分配一次，出入两侧共用；批量插入可预留连续范围。首版不复用已删除 EID，新 WAL 保存分配结果，checkpoint 保存分配高水位。

| 布局 | 邻接记录 | 属性访问与更新 |
|---|---|---|
| bundled | 邻居 VID、EID、可见性、内嵌属性 | 遍历直接读取；更新复制涉及的出入邻接页 |
| unbundled | 邻居 VID、EID、可见性 | 按 EID 直接定位属性块，属性更新不修改 CSR |

bundled 须遵守以下约束。

- **不建立双向全量 `EID → 邻接位置` 表，也不增加仅凭 EID 随机查询属性的新接口。**
- 更新、删除和新格式 WAL 使用边表、端点及 EID 标识目标边；在对应端点的邻接范围内定位。
- 事务内允许携带页与槽位提示以复用已有定位；提示绑定页版本，页替换、排序或 compact 后必须重新解析。
- 多重边通过 EID 区分；定位不得只匹配端点或属性值。
- 不默认增加局部 EID 索引；但高度顶点按 EID 线性定位实测为 O(degree)（度 1M 约 139 μs，见本节末「bundled EID 定位实测结论」），必须改为邻接 EID 有序 + 二分或携带局部 EID 索引。
- 增加 EID 后记录 16B→24B（+50%），遍历每记录实测 +67%，此带宽开销必须计入验收。

bundled EID 定位实测结论（微基准已验证）：

- 按 EID 在邻接内线性定位是 O(degree)：度 1K/64K/1M 分别约 141 ns / 7.6 μs / **139 μs** 每次定位。bundled 边有出/入两条记录，单次更新/删除需定位两侧 → 超级节点上可达 ~280 μs，WAL 重放再定位一次。对超级节点不可接受。
- 邻接按 EID 有序 + 二分定位是 O(log D)：同度数约 11 / 38 / 76 ns，度 1M 时比线性快 ~1800×；这是不引入全量 `EID→定位表` 的可行缓解，落在既有“邻接页可排序”允许内。
- EID 有序与“按邻居排序”（遍历/merge 局部性）冲突，一个邻接不能同时按两者排序；故高度顶点需二选一或携带局部 EID 索引。
- 记录加宽：16B→24B（+50%），遍历每记录 +67%（更宽记录 → 每记录更多 cache line）。

CSR 按顶点目录与邻接页组织，高度顶点继续分页。邻接页可搬移、合并、排序，VID/EID 保持稳定。

### Chunk 到文件的映射

```text
ChunkKey → ChunkVersion → 物理块引用及其逻辑范围
                           → 内存块
                           或 ObjectSlice(object_id, offset, length, checksum)
```

块身份包含稳定的存储模块、属性列及逻辑块编号，不依赖可重排的 schema 编号。

多个块和数据段打包到不可变对象文件，目标 **64 MiB**，允许未满封存。映射通过持久化分页目录树保存：

```text
CURRENT → manifest → 模块描述符及目录根
                         → 目录页 → ObjectSlice
```

只复制变化目录页及祖先页；对象位置通过稳定 ID 解析，不持久化内存指针或绝对路径。

单个逻辑 chunk 可引用多个前缀、后缀或子页；这些引用也需持久化并纳入 GC，不能假设一个 chunk 永远对应一个文件切片。多切片读路径必须满足下述「读路径实测约束」，否则随机遍历会因每访问切片搜索付出 +150~200% 代价。

### 读路径实测约束（微基准已验证）

微基准实测了连续列 vs 分块列的扫描/遍历（int64，Apple Silicon L2=4 MiB，128 MiB~4 GiB 单列），据此固定读路径约束：

- `rows_per_chunk` 硬下限 256 KiB：扫描回退由块大小主导，大表下 32 KiB 块约 +137%、256 KiB 约 +5~14%、512 KiB 约 0%；扫描密集的 AP 表优先 512 KiB。
- 内存读路径用扁平 O(1) `chunk_id → 块指针` 索引：持久化分页目录树只服务增量 checkpoint（复制变化页及祖先页），不得作为每次访问的遍历路径，打开时解析为扁平索引。
- 单切片遍历回退约 +10%（内存受限）到 +55%（工作集部分命中缓存），为最优情况（连续块 + 扁平目录）；目录 footprint 约 32 KiB/GiB（裸指针），约 16~128 GiB 单列才脱离 L2，GB 级目录仍常驻缓存，chunk 数按 ~4096/GiB 线性增长，非瓶颈。
- 多切片遍历惩罚（+150~200%）来自每次访问的切片搜索分支失败，不是数据散布：连续打包治好扫描（+42~67%→~0%）但治不好遍历，只有「连续打包 + 直接解析」才回到基线。故多切片读路径必须连续打包（同一 object/mmap 区）并直接解析，优先等大小子页（slice index 由 `slot >> log2(per)` 直接算出），避免变长前缀/后缀的每访问搜索。

## 3. 事务、并发 Insert、删除与重插

### COW 更新

- `CowDetachState` 改为事务内块写集合；存储接口根据 VID/EID 或邻接位置执行 `EnsureWritable()`。
- 同事务同块只复制一次，批量修改按块组织。
- 两类 COW 事务保留准入、WAL 和发布职责；分配、目录构造、冻结及视图准备在 WAL 提交边界之前完成。
- Abort 丢弃私有块；旧快照继续持有旧块。
- 读取使用块内访问和连续 span；不通过拼接整列兼容原来的裸指针接口。
- 字符串及其他借用视图持有所需版本或 pin。

### 稀疏更新的候选优化

对定长属性比较以下方案，再根据读写总成本决定是否采用。微基准已量化三方案（见本节末「写路径实测结论」）：整块 COW 对稀疏/分散更新写放大不可接受，应改以小子页 COW 为基线；首版不默认引入属性 delta：

| 方案 | 更新与持久化单位 | 主要代价 |
|---|---|---|
| 整 chunk COW | 同事务首次修改复制整块，checkpoint 写最终脏块 | 稀疏更新复制和写盘放大 |
| 较小子页 COW | 逻辑 chunk 内仅复制、持久化涉及的子页 | 更多物理引用、目录元数据和扫描边界 |
| 有界属性 delta | 不可变 Base 加 `local_slot → 新值` 增量 | 点查覆盖解析、扫描合并、版本及恢复复杂度 |

若采用属性 delta：点查优先解析当前快照的增量覆盖，扫描在批次内合并；checkpoint 可直接持久化增量并复用 Base，不要求每次合并基础块。增量及其基础块引用属于 `ChunkVersion`，需同步适配目录、恢复与 GC。同槽位重复更新只在不影响旧快照时折叠；Abort 丢弃私有增量。段数、字节数和更新密度须有明确上限，合并只处理所属 chunk。

该候选方案只优化 COW 属性更新，普通 Insert 继续共享追加快路径。VID/EID 始终稳定，不采用 zvec 更新时更换 global doc ID、复制完整文档的身份与更新策略，也不引入 bundled 全量 EID 定位表。

### 写路径实测结论（微基准已验证）

微基准量化三方案（1 GiB 单列、4096 个 256 KiB chunk、1000 更新/批；delta 读回在 128 MiB 列测）。

写放大（复制 + checkpoint，相对实际改动字节）：

| 更新模式 | 整块 COW | 小子页 COW(4 KiB) | 属性 delta |
|---|---|---|---|
| 单值 / 同槽高频 | 65536× | 1024× | 2× |
| 随机分散(1000) | 57803×（写 441 MiB） | 1021× | 2× |
| 块内集中(1000) | 66× | 66×（铺满全部子页时退化到整块） | 2× |

delta 读回（vs 物化列）：点查即使 0.1% 稀疏度也 +308%（hash 覆盖）/ +512%（有序数组覆盖），随密度升至 +1417% / +2721%；扫描合并 ≤0.1% 约 +5%、1% 约 +303%、10% 约 +9986%。换覆盖结构救不了点查——两种结构都因访问独立散布的覆盖结构额外缓存 miss，有序数组还因二分分支预测失败更慢。

结论：
- 拒绝整块 COW 作 TP 更新基线（稀疏/分散 65536× / 57803× 不可接受），改以小子页 COW 为基线（稀疏 1024×、比整块好 64×，物化进连续块无读回惩罚）。
- 属性 delta 不作默认（数据佐证原判断）：写放大 2× 最优，但点查 +300% 起为固有代价、扫描合并随密度爆炸；仅当写放大主导（高 checkpoint 频率 + 稀疏更新）且能硬性 bound 密度（≤1%）时才考虑。
- 子页大小是权衡：更小写放大更低，但目录元数据与扫描边界更多（见「读路径实测约束」）。

### 并发 Insert 快路径

普通 Insert 保留“WAL → 并发应用 → 完成时间戳”的路径，**不复制旧块、不按事务发布图根、不维护持久化目录树**。

- 多个 Insert 共享 `AppendableChunk`，预留互不重叠的行槽位后直接写入。
- 块内数据在写完前保持不可见；属性、引用及相关结构完成后发布记录，全事务完成后推进现有连续可见时间戳前沿。
- PK 唯一性在 WAL 前通过事务级键预占完成；短临界区限制在对应键或索引桶，不增加表级提交锁。
- 内存定位采用地址稳定的分段目录；只在跨块时发布新指针，不使并发读者引用失效。
- 块首次修改时标脏，批量汇总；不逐行操作共享哈希集合。
- VARCHAR/LIST 使用执行槽持有的追加段或批量预留区域，仍归属于对应描述符 chunk。
- **普通 Insert 提交不封存数据段。** 块满且预留写入结束，或 UPDATE/checkpoint 排空 Insert 后，才封存。
- 已封存的未满逻辑块允许存在独立追加后缀，避免后续插一行先复制旧前缀；维护边界合并为有界结构，相关搬移成本纳入验收。
- 插边保留顶点级局部协调，不因多个顶点属于同一 chunk 而增加 chunk 级锁；邻接页满时链接新页。
- 在 WAL 提交前准备必要容量与资源，使用预分配池摊薄成本；不得在 WAL 成功后通过普通 Abort 掩盖容量不足导致的部分应用。

WAL 前准备与 PK 预占按以下协议执行。

1. 收集完整事务的新建主键，按稳定表身份及类型化主键的确定顺序去重、预占；事务内重复键按现有语句语义处理。预占使用独立于可见 PK 映射的事务所有权标记，不向读者暴露未完成记录，也不跨 WAL I/O 持有索引桶锁。
2. 遇到其他事务持有的键预占，在 WAL 前返回冲突并释放本事务已有预占，不持有键或 Insert 准入等待对方的可见时间戳。已存在记录按语句语义处理；若属于本事务不可见的较新写入，则返回冲突；若是同 PK 已删除记录，则进入下述整体 COW 重试流程。
3. 全部键校验完成后，预留槽位、变长空间、邻接页和索引容量，形成最终 redo。预占持续到数据及索引全部应用、事务完成时间戳已标记之后；期间其他事务不能通过同键校验。资源准备失败发生在 WAL 前。
4. WAL 前取消时释放键预占和私有资源，废弃槽位保持不可见，完成原时间戳并释放准入；高水位与存活数量分别维护，不能因取消而移动其他事务已预留的槽位。重试必须取得新的事务上下文，不能沿用已完成的时间戳。
5. WAL 成功后只执行已准备的应用步骤，不再进行可失败的唯一性判定或普通容量扩展。若仍发生无法完成应用的错误，或 WAL 追加结果不确定，停止服务并通过恢复确定结果，不能释放为普通 Abort 后继续接收写入。恢复按已提交 redo 重建 PK 映射，预占标记不持久化。

预占协议 correctness 审查结论：

- 现状已确认竞态：`vertex_table.cc` 的 `insert_vertex_pk_internal` 是 check-then-act——先 `indexer.get_index` 判存在、再 `indexer.insert`（`insert_absent_typed` 仅 `fetch_add` + 槽位 CAS，不按 key 去重）。并发 Insert 同新键会双双通过 `get_index`、各拿一个 vid、各占一个哈希槽 → 同 PK 两个 vid，唯一性被破坏。上述 WAL 前预占即为堵此洞。
- **预占原子性是命门**：步骤 1/3 的“同键不能通过校验”依赖每键/桶的**单次原子 check-and-set**（CAS 占用所有权槽或短桶锁），且必须与可见 map 的 `get_index`/`IsVertexValid` 及删后重插路径线性化。若预占本身有竞态，WAL 唯一性与恢复重建会同时失效。方案需明确预占的原子原语与线性化点。
- **变长容量必须在 WAL 前完全预留**（步骤 3/5）：这要求先修 `storages/README.md §5.4`——当前 `ListPropertyColumn` 从 checkpoint 加载后 `elements` 零冗余、`insert_safe=false` 插非空 list 必抛。不修则步骤 5“WAL 后不再扩容”无法兑现 → 触发 fail-stop。
- **预占生命周期 vs 65536 时间戳窗口**：步骤 3 预占持续到“完成时间戳已标记”，即跨 WAL I/O 持有。WAL 卡顿会让时间戳长期 outstanding，逼近 `TimestampWindow::kWindowSize=65536` → 背压阻塞新 Insert、read_ts 无法推进。方案应 bound 预占生命周期并把维护水位 margin 与之关联。

### 删除与同 PK 重插

删除只改变可见性及相关边、索引，不前移属性行，不改变其他记录的块内逻辑槽位。

- 部分删除的定长块保留空洞，首版不增加槽位重映射。
- 全块无存活行时允许释放属性载荷，但保留逻辑范围和删除状态。
- 不把已删除 VID 分配给其他 PK。
- 同 PK 重插沿用当前复用 VID 的行为，重新初始化全部属性、默认值和索引，设置新的可见性时间戳。
- 旧关联边保持删除，旧快照仍读取旧记录。

同 PK 重插涉及旧槽位覆盖，自动提交语句采用 **WAL 前整体中止 Insert 尝试，再在 COW 事务中重新执行完整语句**，不直接迁移已计算的写集合：

1. 保存原始语句和拥有自身数据的参数，丢弃尚未写入 WAL 的 redo、暂存结果和资源预留，释放全部 PK 预占。
2. 销毁算子上下文、借用视图和临时 VID/边位置，释放原 snapshot guard，完成原 Insert 时间戳并释放准入；不能持有这些准入或 pin 等待 COW。
3. 取得新的 COW 时间戳和当前图快照，按当前 schema 校验或重新准备执行计划，重新执行所有读取、表达式、主键检查、端点解析及约束校验。切换期间端点被删除、属性或 schema 被修改时，使用新快照重新判断，不能只复查重插主键。
4. 新执行的全部结果与写入仅在 COW 提交成功后返回；原 Insert 尝试不得提前发送结果或执行不可重试的外部副作用。含此类操作的语句从开始即选择 COW，重试不重新选择 Insert。

显式多语句写事务从开始使用 COW，不在已返回前序语句结果后切换快照。底层批量写接口若没有可重新执行的语句，应按拥有自身数据、以逻辑主键标识的输入重新执行完整批次并重新校验全部端点；不能重建的读取依赖返回 WAL 前事务冲突，由调用方重试整个事务，不能静默继承旧执行上下文。

PK→VID 映射、分配高水位及可见性状态均需持久化，高水位不能用存活数量代替。

## 4. 局部 Compact、Checkpoint 与回收

分别维护以下两类状态。

- `dirty_chunks`：尚未持久化的块版本。
- `compact_candidates`：存在删除、变长垃圾、邻接增量或整理需求的范围。

定长属性覆盖更新只标脏；未处理候选通过块级统计和目录元数据跨 checkpoint、重开保留。

局部整理遵循以下规则。

- Mutable CSR 只处理候选邻接页；Immutable CSR 先分页，再执行页内搬移。
- CSR 增量最多 4 段，或达到基页大小的 25% 时合并；空基页按目标页大小封存。
- 变长段当前版本无效字节比例达到 25% 时，扫描所属描述符 chunk，将存活值写入新段并更新相关描述符。
- bundled compact 搬移完整邻接记录，保留 EID；没有全量定位表需要同步更新。
- 整理不改变存活 VID/EID，不直接覆盖旧快照引用的块。
- 读取始终保证可见性和既有排序语义，不能依赖以后 compact 才正确。
- 局部 compact 保留时间戳；全局编号压紧和时间线重置作为独立维护。

可选整理按扫描/搬移字节预算和时间预算调度，优先处理垃圾回收收益高或读放大明显的候选；按可独立发布的局部单元执行，时间预算在单元之间检查。超预算候选保留到后续维护，不能阻止本次脏数据持久化。结构硬上限与可选阈值分开：追加后缀、CSR 增量及候选属性 delta 的硬上限必须在继续增长前满足，必要整理不能无限推迟，其成本单独计入写入或 checkpoint 延迟。

若采用属性 delta，合并策略同时考虑段数、字节数、更新密度和点查/扫描合并成本；不能为了 checkpoint 无条件重写 Base。持续写入下需验证整理积压和读放大有界。

Checkpoint 按以下顺序执行。

1. 取得现有维护边界，排空写入，确定图版本及 `base_timestamp`。
2. 封存追加数据，完成必要的结构整理，在预算内处理达到阈值的可选局部候选。
3. 写最终版本中未持久化的数据块并同步对象。
4. 自底向上写变化目录页，再写 manifest，准备新 WAL epoch。
5. 原子发布 `CURRENT`。
6. 安装新目录及持久化引用，切换 WAL，清理已覆盖脏状态和已完成候选。

多次提交修改同一块只写最终版本。普通 checkpoint 不消费 live graph、整表 reopen 或重置时间线；32 位时间戳空间由下述独立维护协议管理。

### 时间线维护

- 为普通事务设置低于有效时间戳上限的维护水位，排除无效值和删除标记等保留编码。余量至少覆盖允许的最大在途预留量与准入竞争；水位比较和预留采用同一原子协议，不能依赖后台检查及时发生。接近水位时请求维护，在释放本次准入后等待或重试，不持有自己的事务租约等待排空。
- 增加不预留普通写时间戳的排他维护入口，与 UPDATE/checkpoint 使用同一准入状态机互斥：关闭新事务准入，排空已进入的写入及读者，确认全部旧时间戳和快照 pin 已释放。已到上限时仍可进入此路径，不能依赖 `acquire_update_timestamp()` 成功。
- 在私有维护图中重写所有时间戳相关状态，保留删除语义、PK 映射及 VID/EID，高水位不随时间线重置。生成新 timeline epoch、基线时间戳为零的完整 checkpoint，以及绑定该基线的新 WAL epoch；这次全量处理属于独立维护成本。
- 同步数据、目录、manifest 和新 WAL epoch 后原子发布 `CURRENT`，再安装图版本、重置内存时间戳窗口与读写前沿、切换所有 WAL writer，最后开放准入。新格式 manifest/WAL 标明 timeline epoch，恢复只重放当前基线所属时间线的日志，不能把旧时间线的大时间戳日志应用到新基线。
- 发布前失败保留旧图、旧计数器和 WAL；已到维护水位时保持写入关闭，允许对旧图读取及再次维护，不能为继续写入而回绕计数器。发布后安装或 WAL 切换失败则停止服务，重开依据 `CURRENT` 完成恢复，不回退到旧时间线。
- 启动时在初始化普通事务的 VersionManager 之前检查恢复后的时间戳高水位；可写打开必要时走同一排他维护流程，避免在时间戳已耗尽时初始化直接失败。只读打开不触发重写，允许读取旧时间线。

ReserveWriteTimestamp 落地（#7）：当前 `version_manager.cc` 的 `ReserveWriteTimestamp` 只在 `candidate == UINT32_MAX(0xFFFFFFFF)` 判耗尽，允许普通写时间戳取到 `0xFFFFFFFE`——恰为保留编码 `MAX_TIMESTAMP`（`types.h`；且 `INVALID/DELETED_TIMESTAMP=0xFFFFFFFF`），会与 COW 读时间戳 `kReadTimestamp` 冲突，且未给在途窗口留余量。须改为 `candidate >= 维护水位` 即返回“需维护”，水位 = `MAX_TIMESTAMP - margin`，margin ≥ `kWindowSize(65536)` + 准入竞争余量，确保普通时间戳永不触及保留编码、且在途预留不越界。触发“需维护”时走上述排他维护入口重置时间线后重试，而非直接抛 “timestamp space exhausted”。（水位判定已落地：`version_manager.h` 定义 `kTimestampGuardBand=2×kWindowSize`、`kWriteTimestampWatermark=UINT32_MAX-guard`，`ReserveWriteTimestamp` 与 `init_ts` 改用 `>=水位` 判定，`WalReplayVersionManagerTest` 单测覆盖；自动维护触发+重试待时间线维护协议就绪后接入。）

属性、主键映射、删除状态、索引和目录共同构成持久化边界，分别统计写盘量，避免全量写放大转移到辅助模块。某个物理块已落盘不能单独授权删除 WAL；只有覆盖完整事务状态的 checkpoint 成功发布后，才可回收已覆盖日志。

### 恢复与格式迁移

- 加载 manifest、模块参数和目录根，按需映射数据，再重放基线之后的 WAL。
- 旧 checkpoint 打开后，按旧布局和原有顺序重放旧 WAL，运行在兼容模式；首次成功迁移前的新写入仍使用旧布局及旧 WAL 编码，不生成对外使用的 EID，也不启用会改变旧 WAL 定位语义的局部 CSR 整理。分块优化在迁移成功后生效。
- 首次 checkpoint 取得排他维护边界并排空事务，对包含全部已提交旧格式写入的图创建私有迁移版本，转换分块布局和 EID。bundled 保留内嵌属性布局，为对应出入记录分配一致 EID；多重边逐条建立双向对应，单方向记录独立分配，不合并端点及属性相同的不同边。

多重边出入配对算法（消除“逐条建立双向对应”歧义）：bundled 边插入时出记录(src→dst)与入记录(dst→src)共享同一 (内嵌属性,时间戳)（`edge_table.h` 两侧 put_generic_edge 同 data/ts），但迁移前两侧独立存储、无持久关联。配对规则：对每个 (src,dst)，出/入记录各按 (内嵌属性,时间戳) 分组，组内按位置 1:1 配对赋同一 EID。属性/时间戳不同的边由分组天然区分不会错配；组内完全相同的边位置配对虽任意但语义等价（交换 EID 得同一图）；某组出/入数量不等或自环单侧 → 多余记录按单方向独立分配。成本 O(E·log degree)（一次性迁移，超级节点 O(degree·log degree)）。
- 在一个新格式 checkpoint 内持久化 EID、分配高水位、完整目录和格式版本，并准备绑定该 checkpoint 的新格式 WAL epoch。数据及元数据同步完成后才原子发布 `CURRENT`；随后安装新图和新 WAL writer，完成切换后才重新开放写入。WAL epoch 带编码版本与基线身份，禁止在旧 epoch 中追加新编码记录。
- 首次迁移允许一次全量写盘。发布前失败丢弃私有迁移结果，保留旧 `CURRENT`、旧 WAL 和脏状态；重开仍重放旧格式日志，迁移重试无需复用尚未发布的 EID。只读打开不迁移。
- 发布成功后，即使第一条新格式边更新在下一次 checkpoint 前崩溃，恢复也从已持久化 EID 的新格式基线重放新 WAL。安装或 WAL writer 切换必须在开放准入前完成；此阶段失败或 `CURRENT` 发布结果不确定时停止服务，重开按实际 `CURRENT` 选择基线与日志，不能继续向旧 WAL 写入。

GC 遍历当前版本、仍被持有的旧版本及 staging 的目录和数据段引用。文件无引用时删除；部分失效文件通过独立对象整理回收。仅物理搬迁可保持块版本不变，内容变化则生成新版本。

## 5. 实施顺序与验收

按以下顺序实施。

1. 块目录、对象切片和 GC；打通定长列更新、checkpoint、重开。COW 方案已按「写路径实测结论」定为小子页 COW 基线（整块 COW 稀疏更新写放大不可接受，delta 不作默认）。块布局须满足「读路径实测约束」（`rows_per_chunk` ≥256 KiB、内存扁平读索引、多切片连续打包 + 直接解析）。
2. 变长属性、时间戳、主键映射、WAL 前 PK 预占、共享追加块及同 PK 重插的整体 COW 重试路径。
3. CSR 分页、稳定 EID及局部 compact，分别适配 bundled/unbundled 访问和 WAL。
4. 统一所有 checkpoint 路径，完成旧格式兼容模式、迁移发布协议和无需普通写时间戳的独立维护能力；这些恢复能力完成前不对旧库启用新格式写入。

正确性验收覆盖以下情况。

- 同事务同块只复制一次，跨块更新不复制无关块。
- 多列不同块边界、尾块追加、超大值和嵌套 LIST 正确。
- 预留后乱序完成的并发 Insert 不泄露未完成记录；PK 冲突、资源不足和事务中止处理正确。
- 两个事务争用相同新 PK、反序批量键及较新时间戳先完成时，无死锁或双重成功；冲突在 WAL 前解决。注入资源准备失败及 WAL 不确定结果，验证预占释放、废弃槽位不可见、时间戳窗口无缺口及恢复后的唯一性。
- Insert 与 UPDATE/checkpoint 切换无死锁、丢写或旧块覆盖。
- 同 PK 重插重试间隙，另一 UPDATE 删除其他端点、修改属性或变更 schema，验证完整语句按新快照重执行、旧结果不外泄、临时 VID 和借用视图不被复用；显式事务不发生中途快照切换。
- 删除不移动其他 ID；同 PK 重插完整重置属性，旧边不复活，旧快照可读。
- bundled 遍历直接读取属性；页提示失效后正确重新定位，排序和 compact 后 EID 不变。
- 多重边、自环、单方向 CSR、超级节点及出入记录对应关系正确。
- 覆盖“删除 → checkpoint → 重开 → 同 PK 重插 → checkpoint → 重开”。
- 在数据、目录、manifest、`CURRENT` 和 WAL 切换处注入故障并重复恢复。
- 覆盖旧库带 WAL 迁移、失败重试、只读打开和旧快照持有时的 GC。
- 覆盖“旧库打开 → 兼容模式写入 → 崩溃重开 → 迁移 checkpoint → 新格式边更新 → 下一次 checkpoint 前崩溃重开”，并在迁移发布前后及 writer 切换处注入失败，验证 EID 对应和 WAL 版本/基线选择。
- 用可控的小时间戳上限覆盖并发预留跨维护水位、长事务排空、维护发布前失败重试、发布后切换失败重开、已耗尽库的可写及只读打开，验证旧 epoch 日志不会进入新时间线，VID/EID 和删除状态不变。
- 覆盖未满物理块封存后多次追加、checkpoint、重开，逻辑范围及槽位映射保持不变。
- 验证整理预算耗尽时脏数据仍可完整持久化、候选跨重开保留，结构硬上限不被持续追加突破。
- 若采用子页或属性 delta，覆盖跨子页更新、增量覆盖与批次扫描、重复更新折叠、Abort、旧快照、合并前后恢复及 GC。

性能验收分别记录复制字节、compact 扫描/搬移字节、数据/元数据写盘量、内存占用、吞吐和 P99：

- 固定修改范围并扩大表规模，数据复制、整理和写盘量应基本稳定。
- 稀疏更新评估覆盖单值、集中与随机分散更新、同槽位高频更新及密集批量更新；同时改变 checkpoint 频率，对比三种方案的复制量、数据与目录写盘量、点查/扫描开销、内存和 P99，不仅比较前台写入。
- 分别统计属性、主键映射、删除状态、索引和目录的持久化成本；持续负载下记录整理积压、预算执行及硬上限整理成本，验证读放大和空间放大有界。
- 普通 Insert 必须实现零旧数据块复制、零每事务持久化目录发布。
- 对定长、VARCHAR、LIST、均匀插边和热点插边测试不同并发度；并发 Insert 不接受超出测量波动、可重复的吞吐下降或 P99 上升。
- 同时测试跨块、checkpoint 后追加及 Insert/UPDATE 混合负载，不能将成本转移到维护阶段后宣称无损。
- 代表性扫描和遍历的回退门槛按工作集缓存命中分档（依据「读路径实测约束」）：扫描在 ≥256 KiB 块下应 ≤10%（实测大表约 +5~14%）；遍历 ≤10% 仅在深度内存受限区成立（实测约 +10%），工作集部分命中缓存时实测可达约 +55%，须单独报告而非套用单一 10% 门槛。bundled 新增 EID 的空间与带宽成本单独报告。

PR #1083 已开始落地定长列：保留 256 KiB 逻辑 chunk，覆盖写使用最多 4 KiB 的物理子页；版本化目录记录对象切片，增量 checkpoint 复用干净切片。追加视图在发布前准备可写区，普通 Insert 在预留槽位上写入；同 PK 重插在写 WAL 前切换到 COW。对象共享映射、延迟载荷校验和 2 MiB 分配池用于限制重开与分配成本。目录仍按整列页数重写。这些实现需要独立的端到端吞吐、P99 和维护阶段测量，不能据此认定并发 Insert 已无性能损失。

变长列、bundled CSR 的稳定 EID、局部整理和整理预算尚未落地。读路径（连续列 vs 分块列的扫描/遍历）已有微基准，结论见「读路径实测约束」；这些数据不能替代当前实现的性能验收。

## 6. 落地优先级、依赖与状态

本节汇总各修订项的优先级、依赖与落地状态；详细论证见对应小节（不重复）。优先级：**P0** = 动工前必须解决（correctness/前置依赖）；**P1** = 基线设计变更；**P2** = 细节/条件项。

| 项 | 优先级 | 详见 | 状态 |
|---|---|---|---|
| PK 预占原子性 | P0 | §3 预占协议 correctness 审查结论 | ⏳ 待编码（gated on 变长预留 + 块地基） |
| 变长容量 WAL 前预留 / §5.4 | P0 | §2 变长与 bulk COPY 结论 | ⛔ 拒绝 spare 止血带；✅ 根本解（appendable/sealed 段）已定；⏳ gated on §5 step1 |
| ReserveWriteTimestamp 维护水位 | P0 | §4 ReserveWriteTimestamp 落地 | ✅ 水位判定已落地（+3 单测）；⏳ 自动维护触发待接入 |
| 小子页 COW 基线 | P1 | §3 写路径实测结论 | ✅ 已定为基线（delta 不作默认） |
| 读路径布局约束 | P1 | §2 读路径实测约束 | ✅ 已定（≥256KiB/扁平索引/打包+直接解析） |
| bundled 高度顶点 EID 定位 | P1 | §2 bundled EID 定位实测结论 | ⏳ 待编码（EID 有序+二分或局部索引） |
| 迁移多重边出入配对 | P2 | §4 多重边出入配对算法 | ✅ 算法已定 |
| bulk COPY 只写脏 chunk | P2 | §2 变长与 bulk COPY 结论 | ⏳ gated on 块地基 |

依赖与建议顺序：

```text
变长预留(§5.4) ──前置──▶ PK 预占原子性
小子页基线 + 读布局 ──地基(§5 step1)──▶ bulk COPY 分块
维护水位 ──支撑──▶ 时间线维护协议
bundled EID 定位 / 迁移配对  独立可并行
```

建议顺序：先 变长预留 → PK 预占（打通并发 Insert 正确性），并行 维护水位；再定 小子页+读布局 的块地基（§5 step1）；随后 bundled EID 定位；迁移配对与 COPY 在地基就绪后收口。

贯穿性根因：多个“默认/基线”选择对 TP 热路径不成立——整块 COW（写放大）、线性 EID 定位（超级节点）、check-then-act PK（并发唯一性）、UINT32_MAX 耗尽判定（编码冲突）；每项均有可落地修正，已写进对应小节。
