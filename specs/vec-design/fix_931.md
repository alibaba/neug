# Issue #931：Cosine HNSW 外部向量表示

## 背景与根因

Issue #931 中，标量 `vector_distance_cosine` 对相同向量返回 `0`，而
`ORDER BY ... LIMIT` 被改写为 HNSW IndexScan 后返回负数。以 1024 维全 1
向量为例，当前 IndexScan 返回 `-31`。

NeuG 标量函数直接基于原始向量计算：

```text
1 - dot(x, q) / (norm(x) * norm(q))
```

ZVec 的 cosine search 会通过 `CosineReformer` 归一化查询向量，再在 HNSW
内部计算：

```text
1 - dot(stored_vector, normalize(q))
```

当 ZVec 自己管理向量时，存储向量会先经过对应的 cosine converter。当前
NeuG 使用 `SearchWithSource`，`HNSWVecSource` 直接返回 `VecColumn` buffer 中的
原始 FP32 向量，绕过了存储侧 converter。因此实际结果是：

```text
1 - dot(x, normalize(q))
```

相同的 1024 维全 1 向量满足 `norm(x) = 32`，所以结果为 `1 - 32 = -31`。

L2 和 IP 的无量化 FP32 路径不要求单位化：L2 使用原始向量计算平方欧氏
距离，IP 内部使用负点积建图并在返回前恢复为正点积。当前不对称问题只发生在
cosine。

## 提议方案

### 方案范围

本阶段不为 HNSW 维护独立的归一化副本，也不修改 ZVec 的
`SearchWithSource` 接口。NeuG 在创建 HNSW 索引时提供 `normalize` 配置，允许
用户明确授权 NeuG 对索引属性列执行 L2 归一化。

`normalize` 是 HNSW 专用的布尔配置，默认值为 `false`：

```cypher
CREATE INDEX item_embedding_hnsw ON Item USING HNSW (embedding)
WITH (metric = 'cosine', normalize = true);
```

只有用户显式指定 `normalize = true` 时，NeuG 才能主动修改属性列中的向量。
没有配置、配置为 `false`，以及使用默认值三者都不得触发数据修改。

该方案的目标是优先修复 cosine HNSW 使用外部原始向量时距离错误的问题。
它以修改用户属性数据为代价，是当前外部向量接口限制下的阶段性方案。未来可以
改为索引私有的归一化向量副本，避免索引 DDL 修改用户数据。

### 各 metric 的行为

| metric | `normalize` | 创建行为 |
| --- | --- | --- |
| cosine | `false` 或未配置 | 抽样检查数据；样本均为单位向量时允许创建，否则拒绝创建并提示配置 `normalize = true` 或由用户预先归一化 |
| cosine | `true` | 先抽样检查；样本已归一化则直接创建索引，否则对属性列执行 L2 归一化后创建索引 |
| ip | `false` 或未配置 | 使用原始向量创建索引，不修改属性数据 |
| ip | `true` | 先抽样检查；样本已归一化则直接创建索引，否则经风险和索引兼容性检查后执行 L2 归一化 |
| l2/l2sq | `false` 或未配置 | 使用原始向量创建索引，不修改属性数据 |
| l2/l2sq | `true` | 先抽样检查；样本已归一化则直接创建索引，否则经风险和索引兼容性检查后执行 L2 归一化 |

IP 和 L2 默认始终保留原始向量。只有用户显式配置 `normalize = true`，才执行与
cosine 相同的归一化流程。需要注意，归一化会改变 IP 和 L2 的数学语义及排序
结果，因此不推荐在 IP/L2 索引上启用该选项。

### 单位向量检查

创建索引前，对当前属性数据执行 sampling 检查，以判断样本是否已经符合 L2
归一化要求。该检查同时用于 `normalize = false` 的创建条件，以及
`normalize = true` 时是否可以跳过归一化步骤。检查至少应满足：

- 使用 `double` 累加平方和，降低高维向量的累计误差；
- 所有元素必须是有限值，拒绝 `NaN` 和正负无穷；
- 属性值及向量元素均不允许为 `NULL`；
- 按统一容差判断 `abs(norm - 1) <= epsilon`，`epsilon` 应定义为实现常量并在
  测试中固定；
- 全零向量保持全零，并视为可接受的 normalized 表示；非全零但 norm
  小于最小阈值的向量仍按非法 cosine 向量处理；
- 错误信息应包含 label、property，条件允许时包含首个失败样本的 VID 和 norm。

sampling 只用于降低创建索引前检查的成本，并不能证明整列全部为单位向量。
因此，当 `normalize = false` 且抽样通过时，NeuG 允许创建索引，但用户需要保证
所有现有及后续向量均已归一化。未被抽中的非单位向量仍可能导致错误距离、错误
排序或降低 HNSW 召回率。用户需要严格正确性保证时，应在导入前全量归一化和
校验数据。

当 `normalize = true` 且 sampling 检查通过时，也直接认为当前 `VecColumn` 已经
归一化并跳过数据转换。这一优化同样存在抽样误判：未抽中的非单位向量不会被
转换，仍可能触发 #931。`normalize = true` 在该路径下表示“允许 NeuG 在抽样
发现需要时修改数据”，而不是对整列已归一化的严格保证。用户需要严格保证时，
仍应在导入前全量归一化和校验数据。后续可以增加强制全量归一化/校验选项，但不
属于本阶段方案。

抽样策略需要保持可复现，例如固定检查前 N 个有效向量并按固定步长取样，不能
使用无固定种子的随机抽样。空表允许通过检查，但不能据此认为后续写入会自动
满足单位向量要求。

### 创建索引流程

当 `normalize = false` 时：

1. IP/L2 直接使用当前 `ArrayColumn`/`VecColumn` 的原始数据创建索引。
2. cosine 先执行单位向量 sampling 检查。
3. cosine 样本检查失败时拒绝创建索引，不修改列和索引元数据；错误信息提示用户
   显式配置 `normalize = true` 或预先归一化全部数据。
4. cosine 样本检查通过时，直接使用当前数据创建索引。此时 NeuG 不保证未抽中
   数据的正确性。

当 `normalize = true` 时：

1. 先执行 sampling 检查。如果全部样本都是单位向量，认为当前 `VecColumn` 已经
   归一化，跳过数据转换并直接使用当前列创建索引。
2. sampling 检查发现非单位向量时，检查同一属性列上的 active 和 pending 索引
   是否与归一化表示兼容。
3. 如果存在依赖原始向量的 HNSW 索引，例如默认配置的 IP/L2 索引，则拒绝本次
   创建。不能在原地修改列后继续使用基于旧数据构建的 HNSW 图。
4. 不在归一化前额外执行一次全量检查。在独立的新 buffer 中单次遍历所有有效
   向量，读取一个向量后立即校验并执行 L2 归一化。禁止直接修改可能被其他图
   快照共享的 `VecColumn` buffer。
5. 全零向量保持全零；如果遍历过程中遇到 NULL、非全零近零向量、非有限值或
   其他无法归一化的数据，立即
   报错并丢弃整个新 buffer。此前已经写入新 buffer 的中间结果不得发布，原列
   保持不变。
6. 全部向量转换成功后，使用新 buffer 创建或绑定 `VecColumn`，然后构建 HNSW
   索引。
7. 只有归一化和索引构建都成功后，才原子发布新列和新索引，并标记 vertex table
   dirty、重建 view。
8. 任一步骤失败都必须丢弃新 buffer 和未完成索引；用户属性列及已有索引保持
   原状。

sampling 通过而跳过转换时，仍需执行不会修改数据的索引兼容性检查，并记录该列
采用归一化物理表示，以便约束后续写入。由于 sampling 可能误判，该标记只表示
系统后续将按归一化规则维护此列，不代表历史数据已经过全量验证。

如果同一列已经有一个 `normalize = true` 的 HNSW 索引，后续索引只有在确认列
当前采用归一化表示且 metric 配置兼容时才能创建。至少禁止以下组合：

- 已有 `normalize = false` 的 IP/L2 HNSW，再创建会修改列的索引；
- 已有基于原始数据构建的 HNSW 图，再对共享列执行归一化；
- active 与 pending 索引对同一列要求不同的物理表示。

不能只根据 metric 名称推断兼容性，索引元数据必须持久化最终采用的 normalize
配置。

### 后续写入和索引维护

仅处理建索引时已有的数据不足以修复 #931。只要属性列被
`normalize = true` 标记为采用归一化表示，无论创建时实际转换了数据还是因
sampling 通过而跳过转换，后续对该列的 INSERT、UPDATE、SET 和默认值写入都
必须遵循相同规则：

- 非 NULL 新值在写入 `VecColumn` 和调用 HNSW `Append` 前执行 L2 归一化；
- 全零向量保持全零；非全零近零向量、非有限值或无法归一化的值应使整个写事务
  失败；
- HNSW 向量属性不支持显式 `NULL`。INSERT、UPDATE 或 `SET property = NULL`
  一律使整个写事务失败，不为 NULL 定义归一化、默认值替换或索引删除等特殊
  处理；
- 写入列的数据和传给 HNSW 的数据必须完全一致；
- 更新产生的新 index ID 必须指向归一化后的新版本，旧版本按现有 tombstone
  机制处理；
- INSERT 未提供该属性时，如果 schema 能物化出一个非 NULL 默认向量，则把该
  默认向量作为普通输入执行相同校验和归一化；如果最终物化结果是 NULL，则拒绝
  写入；
- 事务失败时，属性修改和索引修改必须一起回滚。

因此，列当前是否采用归一化物理表示不能只存在于创建索引的临时状态中，需要有
可持久化、可在 reopen 后恢复的标记。该标记应由写路径查询，用于保证数据库重启
后的增量写入仍然归一化。如果最后一个要求归一化表示的索引被删除，不能简单地
清除此标记并假设列恢复成原始数据，因为原始向量已经丢失。

### DROP INDEX 和持久化

归一化后的 `VecColumn` 是新的用户属性数据，而不仅是临时索引数据：

- checkpoint 必须保存归一化后的列及 normalize 元数据；
- reopen 后 HNSW、`VecColumn` 和写路径必须采用相同表示；
- 删除最后一个 HNSW 索引并转回 `ArrayColumn` 时，复制的是归一化后的数据；
- `DROP INDEX` 不会、也无法恢复创建索引前的原始向量；
- 删除索引后如果允许新写入原始向量，列中会出现新旧两种表示。因此实现必须
  明确定义：继续保持该列的归一化写入约束，或者禁止相关写入并要求用户显式迁移
  数据。阶段性方案建议继续保持归一化标记，避免静默混合两种表示。

### 用户可见风险和文档要求

用户文档必须在 `normalize` 选项旁明确说明以下风险：

1. `normalize` 默认是 `false`。只有显式配置 `normalize = true` 才会修改属性值。
2. cosine HNSW 的外部向量必须是单位向量。无论是否配置 normalize，NeuG 都
   可能在 sampling 通过后跳过全量转换，因此 sampling 检查不能提供完整保证；
   用户需要严格正确性时应预先全量归一化和校验数据。
3. `normalize = true` 会永久覆盖原始向量，原始模长信息不可恢复。查询属性、
   导出数据、checkpoint 以及删除索引后看到的都是归一化向量。
4. 创建索引不是只读的数据定义操作：启用 normalize 后会改变表中已有属性值，
   也会改变后续写入该属性时实际保存的值。
5. 对 IP 启用 normalize 会使点积失去原始模长信息；对 L2 启用 normalize 会改变
   距离及最近邻排序。IP/L2 默认不归一化，也不推荐启用该选项。
6. 全零向量保持全零，任一参数为全零时 cosine distance 定义为 1；
   NULL、非全零近零向量、NaN 和无穷值会导致索引创建或后续写事务失败。HNSW
   向量属性不支持通过 `SET property = NULL` 删除索引项。
7. 不推荐在同一属性列上混用需要原始向量和需要归一化向量的索引；实现会拒绝
   已知不兼容的组合。
8. sampling 通过但数据中仍存在未抽中的非单位向量时，cosine HNSW 仍可能返回
   负距离或与标量 `vector_distance_cosine` 不一致的结果。

建议在执行 DDL 前备份原始 embedding，或者将归一化结果写入一个独立属性，再在
该属性上创建 cosine HNSW 索引。例如保留 `embedding`，将单位向量写入
`embedding_normalized`，这样可以避免不可逆地丢失原始数据。

### 验收测试

实现至少需要覆盖以下测试：

- 1024 维全 1 向量在 `normalize = true` 后，IndexScan 对相同查询返回约 0，
  不再返回 -31；
- cosine 非单位向量且未配置 normalize 时，抽样命中后创建失败且属性不变；
- cosine 已归一化数据且 `normalize = false` 时可以创建，属性 bitwise 不变；
- `normalize = true` 且 sampling 通过时跳过转换，属性 bitwise 不变；
- `normalize = true` 且 sampling 失败时只遍历一次完成校验和转换，不执行独立的
  全量预检查；
- IP/L2 未配置 normalize 时保持原始属性值和现有查询结果；
- IP/L2 显式配置 normalize 时属性值和距离按新语义变化；
- 创建索引后的 INSERT、SET、非 NULL 默认值写入与建索引时采用同一归一化
  规则；
- 显式 NULL、物化为 NULL 的缺省值、非全零近零向量、NaN 和无穷值使操作失败，
  全零向量保持全零且 cosine distance 为 1，并且
  属性列与已有索引不发生部分修改；
- 同一列上不兼容的 active/pending HNSW 索引组合被拒绝；
- 创建索引中途失败时原属性值、已有索引和规划状态不变；
- checkpoint/reopen 后属性值、normalize 标记、增量写入和查询结果保持一致；
- DROP INDEX 后明确验证返回的 `ArrayColumn` 仍包含归一化数据；
- IndexScan 与禁用索引后的标量 cosine 在允许误差范围内一致。
